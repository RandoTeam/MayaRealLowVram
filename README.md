## 🎯 О проекте MayaRealLowVram

**MayaRealLowVram** — это специализированная модификация и инженерный форк проекта **[Project Maya](https://github.com/mw00/project-maya)** (на базе движка Strata), направленный на запуск флагманской модели **GLM-5.3-Flash** (321B параметров, 18B активных экспертов на токен) на массовых пользовательских конфигурациях с жестко ограниченным объемом видеопамяти: **8 ГБ, 6 ГБ, 4 ГБ и даже 3 ГБ VRAM**.

В оригинале модели такого масштаба требуют серверных ускорителей (A100, H100) либо связок из нескольких RTX 4090/3090. Данный проект использует многоуровневую иерархию памяти (**VRAM → Pinned RAM → NVMe SSD**) с микросекундной маршрутизацией экспертов и новейшими алгоритмическими оптимизациями релиза **v1.1.10**.

## 🚀 Ключевые возможности и ускорения (на базе v1.1.10)

В актуальном релизе v1.1.10 скорость генерации и эффективность работы с памятью были кратно увеличены благодаря внедрению следующих механизмов:

1. **Двухпроходная гибридная аллокация плотных весов (2-Pass Hybrid Dense, `STRATA_GLM_DENSE_VRAM_MB`)**:
   - В оригинале 5.24 ГБ плотных весов требуют $\ge$ 6–8 ГБ VRAM, вызывая OOM на 4GB картах. При выносе всех весов в Pinned RAM шина PCIe Gen3 x8 (~6 ГБ/с) становилась узким горлышком (лимит ~873 мс/ток).
   - Наш гибридный механизм делит веса на 2 прохода:
     - **Проход 1 (VRAM):** приоритетное выделение памяти под наиболее часто вызываемые тензоры — все 34 слоя KDA, проекции Q/K/V внимания, роутеры MoE, слои нормализации и индексаторы (~2.05 ГБ) размещаются в сверхбыстрой локальной видеопамяти GDDR6 (192 ГБ/с).
     - **Проход 2 (Host UVA):** оставшиеся тяжелые матрицы (`output.weight` 1.83 ГБ и общие эксперты 1.36 ГБ) выносятся в Pinned Host RAM через Unified Virtual Addressing (`cudaHostAllocMapped | cudaHostAllocPortable`).
   - Сокращает паразитный трафик по шине PCIe на 61% и ускоряет декодинг с **1153 мс до 680 мс/ток (+70% прирост скорости)** при сохранении **полного контекста 32 768 токенов**!
2. **Аппаратные графы CUDA для KDA (`STRATA_GLM_KDA_GRAPH=1`)**:
   - Захват и мгновенное воспроизведение всех 34 слоев KDA через аппаратные CUDA Graphs устраняют накладные расходы на запуск ядер со стороны CPU (проверено: 442 воспроизведения, 0 инвалидаций графа).
3. **KV Cache Streaming (`--kv-streaming on`, `--kv-resident 20480`)**:
   - Латентный кэш внимания выносится в закрепленную оперативную память (Pinned RAM), а в драгоценной VRAM удерживается только скользящее окно активных токенов.
   - Это освобождает до 1.5–3.0 ГБ VRAM, позволяя разместить в видеопамяти критически важные плотные слои и кэш экспертов.
4. **Интеллектуальный пропуск холодных экспертов (`STRATA_GLM_DISK_SKIP_W=0.15`, `STRATA_GLM_DISK_SKIP_FROM=3`)**:
   - Эксперты, не поместившиеся в VRAM и RAM, при низком весе роутинга отсекаются от чтения с медленного SSD. Это сократило задержку ожидания диска с 334 мс до 57 мс/ток без малейшей потери связности и логики ответов.
5. **Оптимальное разделение вычислений CPU/PCIe (`STRATA_GLM_PCIE_SHARE=0.0`)**:
   - Для экспертов, находящихся в RAM, передача по PCIe на слабый GPU занимает 1.13 мс, тогда как 6 потоков современного CPU (Ryzen 5 5500U / Zen 2+) вычисляют эксперта локально всего за 0.50 мс. Отключение передачи RAM-экспертов на GPU освобождает шину PCIe и экономит ~168 мс на токен.
6. **Оптимизированные AVX2 MoE-ядра для CPU (`STRATA_GLM_CPU_MT`, `STRATA_GLM_CPU_1T`)**:
   - Мульти-токенные и одно-токенные векторные ядра ggml с декодированием знаков в регистрах ускоряют вычисления на процессорах AMD Zen 2/3/4 и Intel Core на 25–35%.
7. **Многопоточное чтение NVMe (`STRATA_GLM_DISK_READERS`)**:
   - Параллельные очереди чтения SSD сокращают время холодного старта и обработки длинных промптов (до +50% на быстрых NVMe).
8. **Эвристика для 4GB VRAM (DFlash2 offload)**:
   - На картах с $\le$ 4 ГБ VRAM спекулятивный драфтер DFlash2 отключается, что высвобождает 717 МБ драгоценной видеопамяти и устраняет 20% штраф на верификацию драфта при узкой шине PCIe.

## 🔬 Экспериментальный базовый стенд (Tier 3: 4 GB VRAM)

Для отработки, профилирования и тестирования проекта используется реальный ноутбук:
- **Устройство:** Ноутбук Acer Aspire A715-42G (x64)
- **Видеокарта (dGPU):** NVIDIA GeForce RTX 3050 Laptop GPU (4 GB GDDR6, GA107, sm_86, TGP 60W)
- **Операционная система:** Windows 10 Pro 64-bit (Build 19045, WDDM 2.7)
- **Центральный процессор:** AMD Ryzen 5 5500U (6 ядер / 12 потоков, до 4.04 ГГц, AVX2)
- **Оперативная память:** 32 GB DDR4-3200 (Dual-Channel, ~21 GB свободно в покое)
- **Файл подкачки (Pagefile):** 16.0 GB (общий виртуальный лимит ~47 GB)
- **Накопитель:** WD PC SN530 NVMe SSD 512 GB (PCIe Gen3 x4, чтение до 2400 МБ/с, >180 GB свободно)
- **Программный стек:** Python 3.12, MSVC Build Tools 2026 (v19.51), CMake 4.4, CUDA 12.8.

Подробная спецификация стенда приведена в документе **[`docs/BASELINE_HARDWARE.md`](docs/BASELINE_HARDWARE.md)**.

## 📊 Матрица адаптации по уровням VRAM

| Уровень | Конфигурация GPU | Квант / Настройки | Распределение памяти | Реальная скорость декодинга |
| :--- | :--- | :--- | :--- | :--- |
| **Tier 1** | **8 GB VRAM** (RTX 3070/4060) | **Maya-S24** + DFlash2 | 100% Dense в VRAM, ~30% экспертов в VRAM, ~65% в RAM | **~12–18 tok/s** (55–80 мс/ток) |
| **Tier 2** | **6 GB VRAM** (RTX 3060/2060) | **Maya-S24** | 100% Dense в VRAM, ~15% экспертов в VRAM, ~75% в RAM | **~6–10 tok/s** (100–165 мс/ток) |
| **Tier 3** | **4 GB VRAM** (Базовый стенд RTX 3050) | **Maya-S24** (32k контекст!) | **2-Pass Hybrid Dense:** 2.05 GB в VRAM, 3.19 GB в UVA; 42 экспертных слота в VRAM, 75% в RAM, пропуск хвоста SSD | **~1.47 tok/s** (**680 мс/ток**, ускорение +70% с 1153 мс) |
| **Tier 4** | **3 GB VRAM** (GTX 1060 3GB / MX) | **Maya-S24** + Ultra-Low | 1.2 GB Dense в VRAM, 4.0 GB в UVA; эксперты в RAM + Disk Skip | **~0.9–1.2 tok/s** (850–1100 мс/ток) |

## 📥 Загрузка моделей

Для максимальной надежности и прозрачности в репозиторий включен автономный скрипт загрузки, полностью повторяющий структуру путей Project Maya (`C:\AI\Maya-data\models\<quant>`):

### Интерактивный запуск:
```bat
DOWNLOAD-MODEL.bat
```
В интерактивном меню доступны:
1. **Dry-Run (проверка):** проверяет доступность удаленных ссылок на Hugging Face, свободное место на диске и структуру папок без скачивания данных.
2. **Скачать Maya-S24 + DFlash2:** скачивает модель с Q4_K вниманием (~94.7 ГБ) + файлы Vision (~1.14 ГБ) + спекулятивный драфтер DFlash2 (~0.7 ГБ).
3. **Скачать Maya-S24 без драфтера:** только веса модели и Vision.
4. **Скачать базовую Maya-S-v2:** оригинальный квант IQ2_XXS.
5. **Проверка контрольных сумм:** сверяет SHA-256 хэши скачанных файлов.

### Запуск через командную строку:
```bash
# Проверка ссылок и готовности диска:
python download_model.py --model Maya-S24 --with-dflash --dry-run

# Скачивание модели Maya-S24 с докачкой и проверкой SHA-256:
python download_model.py --model Maya-S24 --with-dflash
```

## 🛠 Запуск и сборка

> 📖 **Пошаговое руководство по чистой установке и восстановлению:**  
> Исчерпывающая пошаговая инструкция по установке всех зависимостей (MSVC, CUDA, Python, Git), настройке файла подкачки, первой сборке и развертыванию на чистой ОС Windows приведена в документе **[`docs/FRESH_OS_RESTORATION_GUIDE.md`](docs/FRESH_OS_RESTORATION_GUIDE.md)**.  
> Готовый эталонный конфигурационный файл: **[`configs/maya-s24-lowvram-4gb.example.json`](configs/maya-s24-lowvram-4gb.example.json)**.

1. Убедитесь, что установлен компилятор C++ и CUDA Toolkit (CUDA 12.0+ / 12.8):
   ```bat
   python maya.py --check
   ```
2. Запустите компиляцию и инициализацию через:
   ```bat
   START-MAYA.bat
   ```
3. Скопируйте эталонный конфиг с калиброванными Low-VRAM переменными:
   ```bat
   copy configs\maya-s24-lowvram-4gb.example.json maya-maya-s24.json
   ```
4. Откройте веб-интерфейс в браузере: `http://127.0.0.1:8080`.

## ⚙️ Оптимальные параметры конфигурации (Environment Flags)

Для тонкого управления распределением памяти и ядрами инференса движок Strata поддерживает переменные окружения:

| Переменная | По умолчанию | Значение для 4GB (RTX 3050) | Описание |
| :--- | :--- | :--- | :--- |
| `STRATA_GLM_DENSE_VRAM_MB` | `0` (авто / 0=UVA) | `2100` | Лимит VRAM (в МБ) для плотных слоев в 1-м проходе. 2100 МБ вмещает все 34 KDA слоя + Q/K/V + роутеры + нормы. |
| `STRATA_GLM_RESERVE_MB` | `256` | `128` | Резерв VRAM под драйвер WDDM. Значение 128 МБ позволяет выделить 42 слота экспертов (1 слот/слой). |
| `STRATA_GLM_PCIE_SHARE` | `1.0` | `0.0` | Доля RAM-экспертов, передаваемых на GPU. `0.0` считает эксперты из RAM на CPU, разгружая шину PCIe. |
| `STRATA_GLM_DISK_SKIP_FROM` | `0` (выкл) | `3` | Номер активного эксперта (из Top-8), начиная с которого проверяется порог веса роутинга. |
| `STRATA_GLM_DISK_SKIP_W` | `0.0` | `0.15` | Порог веса эксперта, ниже которого холодный эксперт на SSD пропускается (экономия до 280 мс/ток). |
| `STRATA_GLM_KDA_GRAPH` | `1` | `1` | Включение аппаратных CUDA Graphs для 34 слоев KDA (устраняет CPU launch overhead). |
| `STRATA_GLM_CPU_SPLIT` | `8` | `8` | Количество потоков CPU для вычисления MoE-экспертов ggml AVX2. |

### Пример запуска сервера с полным контекстом 32 768 токенов:
```bat
:: Установка оптимальных флагов для 4GB VRAM
set STRATA_GLM_DENSE_VRAM_MB=2100
set STRATA_GLM_RESERVE_MB=128
set STRATA_GLM_DISK_SKIP_W=0.15
set STRATA_GLM_DISK_SKIP_FROM=3
set STRATA_GLM_PCIE_SHARE=0.0
set STRATA_GLM_KDA_GRAPH=1

:: Запуск Strata Engine
build\strata.exe --glm-pack C:\AI\Maya-data\models\Maya-S24\pack --max-context 32768 --prefill auto --kv-streaming on --expert-profile data\expert-profile-glm.bin
```
