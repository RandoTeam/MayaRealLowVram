## 1. Введение и ключевые принципы

Модель **GLM-5.3-Flash** (321B MoE) содержит 5.24 ГБ плотных весов (внимание, recurrent KDA слои, роутеры, нормы) и 2688 экспертов. В штатном режиме на видеокартах с 4 ГБ VRAM инференс невозможен, так как:
1. Модель драйверов Windows (WDDM) резервирует 600–800 МБ под рабочий стол и интерфейс, оставляя для вычислений около **3.2–3.4 ГБ чистой VRAM**.
2. Попытка выделить все плотные слои в VRAM приводит к мгновенной ошибке `CUDA Out of Memory`.
3. Попытка вынести все плотные слои в оперативную память (Host UVA) упирается в пропускную способность шины PCIe Gen3 x8 (~6 ГБ/с), ограничивая скорость генерации до 1153 мс/токен.

В нашем форке реализована **2-проходная гибридная аллокация (2-Pass Hybrid Dense)**:
- **Проход 1 (VRAM):** 2.05 ГБ критических слоев (все 34 слоя KDA, проекции Q/K/V, роутеры MoE, нормы) удерживаются в высокоскоростной памяти GDDR6 (192 ГБ/с).
- **Проход 2 (Host UVA):** 3.19 ГБ тяжёлых хвостовых матриц (`output.weight` 1.83 ГБ и общие эксперты 1.36 ГБ) выносятся в Pinned RAM.
- **Пул экспертов:** Резерв WDDM снижен до 128 МБ, что оставляет в VRAM место для **42 слотов экспертов** (по 1 слоту на слой).
- **CPU Offload:** Эксперты в RAM рассчитываются процессором Ryzen по AVX2 (0.50 мс против 1.13 мс по PCIe), шина PCIe освобождается.
- **Disk Skip:** Холодные эксперты на SSD с весом $\le 0.15$ пропускаются.

В результате система работает со скоростью **~680 мс/токен (~1.47 tok/s)** при **полном контекстном окне 32 768 токенов**.

## 2. Подготовка операционной системы (Windows 10/11 x64)

На свежей ОС Windows необходимо выполнить два критических действия:

### 2.1. Настройка фиксированного файла подкачки (Pagefile)
> **КРИТИЧНО:** Windows WDDM и закрепление страниц памяти (Pinned Memory) расходуют лимит фиксации (Commit Limit). При стандартном автоматическом размере система откажет в закреплении оперативной памяти для экспертов.

1. Нажмите `Win + R`, введите `sysdm.cpl` и нажмите Enter.
2. Перейдите на вкладку **Дополнительно (Advanced)** $\rightarrow$ в блоке «Быстродействие» нажмите **Параметры (Settings)**.
3. Перейдите на вкладку **Дополнительно (Advanced)** $\rightarrow$ в блоке «Виртуальная память» нажмите **Изменить (Change)**.
4. Снимите галочку «Автоматически выбирать объем файла подкачки».
5. Выберите быстрый NVMe SSD (диск `C:`).
6. Выберите **Указать размер (Custom size)**:
   - **Исходный размер (Initial size):** `16384` МБ (16 ГБ)
   - **Максимальный размер (Maximum size):** `24576` МБ (24 ГБ)
7. Нажмите кнопку **Задать (Set)** $\rightarrow$ **ОК**.
8. Перезагрузите компьютер.

### 2.2. Освобождение видеопамяти от фоновых программ
Перед запуском инференса на 4GB карте закройте ресурсоёмкие приложения с аппаратным ускорением GPU (браузеры с сотнями вкладок, Discord, Steam, Telegram), либо отключите в них "Аппаратное ускорение графики" в настройках.
Проверьте доступную память через терминал:
```powershell
nvidia-smi
```
В графе `Memory-Usage` занятость должна быть менее 700–800 МБ.

## 3. Установка необходимых инструментов (Prerequisites)

На чистой ОС установите следующие компоненты (строго в указанном порядке):

### 3.1. Видеодрайвер NVIDIA
Установите актуальный драйвер NVIDIA Game Ready или Studio Driver (версия 560+ / 617+).

### 3.2. Visual Studio 2022 Build Tools (Компилятор C++)
Движок Strata компилируется с помощью компилятора MSVC `cl.exe`.
1. Скачайте официальный установщик: [Visual Studio 2022 Build Tools](https://aka.ms/vs/17/release/vs_BuildTools.exe).
2. Запустите установщик и выберите рабочую нагрузку:
   - ✅ **Разработка классических приложений на C++ (Desktop development with C++)**
3. В правой панели убедитесь, что отмечены:
   - ✅ **MSVC v143 — VS 2022 C++ x64/x86 build tools**
   - ✅ **Пакет Windows 10 SDK (или Windows 11 SDK)**
   - ✅ **Инструменты CMake C++ для Windows**
4. Дождитесь завершения установки.

### 3.3. NVIDIA CUDA Toolkit 12.8
1. Скачайте [CUDA Toolkit 12.8](https://developer.nvidia.com/cuda-12-8-0-download-archive) для Windows 10/11 x64.
2. Установите в стандартный путь: `C:\Program Files\NVIDIA GPU Computing Toolkit\CUDA\v12.8`.
3. Проверьте в новом окне PowerShell:
   ```powershell
   nvcc --version
   ```
   Должно вывести: `Cuda compilation tools, release 12.8`.

### 3.4. 64-битный Python 3.12
1. Установите Python через терминал:
   ```powershell
   winget install -e --id Python.Python.3.12 --scope user
   ```
   *(Или скачайте с python.org, обязательно отметив галочку "Add python.exe to PATH")*.
2. Убедитесь, что это 64-битная версия:
   ```powershell
   python -c "import sys; print('64-bit:', sys.maxsize > 2**32)"
   ```
   Должно вернуть: `64-bit: True`.

### 3.5. Git for Windows
```powershell
winget install --id Git.Git -e --source winget
```

## 5. Загрузка модели Maya-S24

Модель должна находиться на быстром NVMe SSD. Стандартный путь: `C:\AI\Maya-data\models\Maya-S24`.

### Вариант А: Интерактивный запуск скрипта
Запустите в папке проекта:
```bat
DOWNLOAD-MODEL.bat
```
В открывшемся меню выберите пункт `2` (**Maya-S24**). Скрипт скачает 3 шардовых файла модели и файлы Vision.

### Вариант Б: Запуск через Python
```powershell
python download_model.py --model Maya-S24
```

### Проверка файлов:
В папке `C:\AI\Maya-data\models\Maya-S24` должны присутствовать:
- `GLM-5.3-Flash-Maya-S24-IQ2_XXS_S-00001-of-00003.gguf` (~32 ГБ)
- `GLM-5.3-Flash-Maya-S24-IQ2_XXS_S-00002-of-00003.gguf` (~32 ГБ)
- `GLM-5.3-Flash-Maya-S24-IQ2_XXS_S-00003-of-00003.gguf` (~31 ГБ)
- Папка `vision/` с файлами `mmproj-GLM-5.3-Flash-F16.gguf` и `GLM-5.3-Flash-vocab.gguf`.

## 6. Первичная сборка движка из исходников (Clean Build)

Для сборки движка используем штатный скрипт `START-MAYA.bat`:

1. Выполните проверку окружения:
   ```bat
   START-MAYA.bat --check
   ```
   Скрипт должен без ошибок обнаружить GPU (RTX 3050), компилятор MSVC, CUDA nvcc и размер оперативной памяти.

2. Запустите сборку:
   ```bat
   START-MAYA.bat
   ```
   **Что произойдёт автоматически:**
   - Создастся изолированное окружение `.venv` с нужными библиотеками.
   - Запустится компиляция `build/strata.exe` через CMake и MSVC (занимает от 10 до 20 минут).
   - При вопросе выбора модели выберите **Maya-S24**.
   - При вопросе драфтера (Drafting?) **ОБЯЗАТЕЛЬНО** выберите вариант по умолчанию (`the model's MTP block`, **НЕ** DFlash2, так как DFlash2 занимает 717 МБ VRAM).
   - Движок выполнит индексацию модели (построит `pack`) и создаст файл конфигурации `maya-maya-s24.json`.

3. Как только сервер начнет стартовать, остановите его нажатием **`Ctrl + C`** в терминале.

## 7. Критический этап: Настройка конфигурации Low-VRAM

> ⚠️ **ВНИМАНИЕ:** Это самый важный шаг. Стандартный установщик генерирует `maya-maya-s24.json` с пустым блоком окружения `"env": {}`. Без калиброванных параметров сервер выделит 700 МБ под резерв, что обнулит экспертный пул на 4GB карте и приведет к краху или сильному падению скорости!

### Вариант 1: Копирование готового шаблона из репозитория
В репозитории подготовлен эталонный файл конфигурации. Просто скопируйте его:
```powershell
copy configs\maya-s24-lowvram-4gb.example.json maya-maya-s24.json
```

### Вариант 2: Ручная правка `maya-maya-s24.json`
Откройте файл `C:\AI\MayaRealLowVram\maya-maya-s24.json` в любом текстовом редакторе (Блокнот, VS Code) и убедитесь, что блок `"env"` содержит точные параметры:

```json
{
 "exe": "C:\\AI\\MayaRealLowVram\\build\\strata.exe",
 "args": [
  "--glm-pack",
  "C:\\AI\\Maya-data\\models\\Maya-S24\\pack",
  "--max-context",
  "32768",
  "--prefill",
  "auto",
  "--kv-streaming",
  "on",
  "--expert-profile",
  "C:\\AI\\MayaRealLowVram\\data\\expert-profile-glm.bin"
 ],
 "cwd": "C:\\AI\\MayaRealLowVram",
 "tokenizer": "C:\\AI\\Maya-data\\models\\Maya-S24\\pack\\tokenizer",
 "model_name": "glm-5.3-flash",
 "gpu": [
  0
 ],
 "sampling": {
  "temperature": 1.0,
  "top_p": 0.95
 },
 "reasoning_effort": "high",
 "lib_dirs": [
  "C:\\Program Files\\NVIDIA GPU Computing Toolkit\\CUDA\\v12.8\\bin"
 ],
 "port": 8080,
 "log": "C:\\AI\\MayaRealLowVram\\maya-maya-s24.log",
 "installer": {
  "models_dir": "C:\\AI\\Maya-data\\models",
  "quant": "Maya-S24",
  "draft": "mtp"
 },
 "env": {
  "STRATA_GLM_DENSE_VRAM_MB": "2100",
  "STRATA_GLM_RESERVE_MB": "128",
  "STRATA_GLM_DISK_SKIP_W": "0.15",
  "STRATA_GLM_DISK_SKIP_FROM": "3",
  "STRATA_GLM_PCIE_SHARE": "0.0",
  "STRATA_GLM_KDA_GRAPH": "1",
  "STRATA_GLM_CPU_SPLIT": "8"
 }
}
```

### Значение каждой переменной в `"env"`:
| Переменная | Значение | Зачем нужна |
| :--- | :--- | :--- |
| `STRATA_GLM_DENSE_VRAM_MB` | `"2100"` | Помещает все 34 слоя KDA, проекции Q/K/V, роутеры и нормы (2.05 ГБ) прямо в память видеокарты GDDR6 (192 ГБ/с). |
| `STRATA_GLM_RESERVE_MB` | `"128"` | Снижает служебный резерв с 700 МБ до 128 МБ. Это освобождает место под 42 слота экспертов прямо в VRAM. |
| `STRATA_GLM_DISK_SKIP_FROM` | `"3"` | Активирует проверку важности экспертов, начиная с 3-го активного эксперта (из Top-8). |
| `STRATA_GLM_DISK_SKIP_W` | `"0.15"` | Если вес эксперта на SSD $\le 0.15$, он не считывается с диска. Сокращает ожидание SSD с 334 мс до 57 мс. |
| `STRATA_GLM_PCIE_SHARE` | `"0.0"` | 100% RAM-экспертов рассчитываются на CPU (Ryzen AVX2). Экономит 168 мс за счёт разгрузки шины PCIe Gen3 x8. |
| `STRATA_GLM_KDA_GRAPH` | `"1"` | Включает аппаратные CUDA Graphs для KDA слоев (устраняет задержки запуска ядер процессором). |
| `STRATA_GLM_CPU_SPLIT` | `"8"` | Задает 8 потоков процессора для параллельных ядер MoE. |

## 8. Запуск сервера и инференса

После настройки конфигурации запустить сервер можно любым удобным способом:

### Способ 1: Стандартный запуск через лаунчер (рекомендуется)
```bat
START-MAYA.bat
```
Запустит дашборд и сервер, автоматически применив параметры из `maya-maya-s24.json`.

### Способ 2: Прямой запуск движка Strata через командную строку
Если требуется запустить сервер в консоли без Python-интерфейса:
```bat
set STRATA_GLM_DENSE_VRAM_MB=2100
set STRATA_GLM_RESERVE_MB=128
set STRATA_GLM_DISK_SKIP_W=0.15
set STRATA_GLM_DISK_SKIP_FROM=3
set STRATA_GLM_PCIE_SHARE=0.0
set STRATA_GLM_KDA_GRAPH=1

build\strata.exe ^
  --glm-pack C:\AI\Maya-data\models\Maya-S24\pack ^
  --max-context 32768 ^
  --prefill auto ^
  --kv-streaming on ^
  --expert-profile data\expert-profile-glm.bin
```

## 9. Проверка работоспособности и метрики скорости

### 9.1. Проверка лога загрузки
Откройте `maya-maya-s24.log`. В нём должны быть строки:
1. `dense weights: hybrid allocation` $\rightarrow$ 2100 МБ в VRAM, остальное в host UVA.
2. `expert pool slots per layer: 1` $\rightarrow$ выделено 42 слота в VRAM.
3. `kda graphs: captured 34 layers`.
4. `READY 32768` $\rightarrow$ модель полностью загружена и ожидает запросов с контекстом 32k.

### 9.2. Проверка веб-интерфейса
Откройте в браузере: **`http://127.0.0.1:8080`**.  
Откроется Web UI Project Maya с графиками мониторинга слоев, экспертов и скорости.

### 9.3. Проверка через API (OpenAI-совместимый эндпоинт)
Выполните проверочный запрос через PowerShell / curl:
```powershell
curl http://127.0.0.1:8080/v1/chat/completions `
  -H "Content-Type: application/json" `
  -d '{"model":"glm-5.3-flash","messages":[{"role":"user","content":"Привет! Назови столицу Франции и объясни в одном предложении."}],"stream":false}'
```

**Ожидаемый результат:**
- Связный ответ: *"Столица Франции — Париж, крупнейший экономический и культурный центр страны."*
- Время декодинга: **~680 мс/токен (~1.47 токенов в секунду)**.
- Никаких зацикливаний, потери связности или галлюцинаций.

## 10. Диагностика типичных проблем (Troubleshooting)

| Симптом | Причина | Решение |
| :--- | :--- | :--- |
| **`CUDA error: out of memory`** при старте | Фоновые программы заняли VRAM, либо в конфигурации остался `--dflash dflash2`. | 1. Закройте браузеры и Discord.<br>2. Проверьте `maya-maya-s24.json`: аргумент `--dflash` должен отсутствовать.<br>3. Убедитесь, что `STRATA_GLM_DENSE_VRAM_MB` равен `2100`, а не больше. |
| **Скорость декодинга медленнее 1100 мс/токен** | Не применились переменные окружения, шина PCIe перегружена. | Убедитесь, что в `maya-maya-s24.json` прописан блок `"env"` с `STRATA_GLM_PCIE_SHARE="0.0"` и `STRATA_GLM_DENSE_VRAM_MB="2100"`. |
| **Пул экспертов: 0 слотов (`slots = 0`)** | `STRATA_GLM_RESERVE_MB` не задан (по умолчанию 700 МБ). | Пропишите `"STRATA_GLM_RESERVE_MB": "128"` в секцию `"env"`. |
| **Падение Windows по нехватке памяти (Commit Limit)** | Не настроен или отключен файл подкачки. | Увеличьте фиксированный размер Pagefile до 16–24 ГБ на SSD (см. Раздел 2.1). |
| **Ошибка при сборке C++ `MSVC not found`** | Не установлены Build Tools 2022 с компонентом C++. | Установите Visual Studio 2022 Build Tools с нагрузкой "Desktop development with C++" и SDK Windows 10/11. |
